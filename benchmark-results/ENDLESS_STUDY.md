# エンドレスモード調査（2026-08-30）

> 製品版未実装。Labでの調査結果と仕様案。

## 結論

- **推奨開始:** 11爆弾。8～10は低密度ゆえ単純No-Guessでは初手開封が大きく、条件C/quality filterでは逆に採用率が低い。11から生成時間と盤面密度のバランスが改善する。
- **推奨通常上限:** 26爆弾。専用quality生成は25～26までp95約0.18～0.39秒、27で3色p95約1.82秒まで悪化した。
- **進行:** Stage 1=11爆弾、以後1面ごとに+1、Stage 16で26爆弾。Stage 17以降は26固定でクリア面数を継続する。
- **生成:** Endlessは3色/4色を**色数別専用生成**にする。Time Attackの共通盤面条件CをEndlessへそのまま流用しない。
- **専用quality filter案:** 選択色No-Guess + color-essential + 初手開封率50%以下 + reasoning round 3以上。subset回数は難易度指標として記録するが初版ではハード条件にしない。
- **ランキング公平性:** 3色/4色を別部門、generator/filter version・Stage→爆弾数・Seed列・初手位置を固定する。初手をプレイヤー自由選択にしない。

## 測定方法

- 9×9、現行Lab Solver/Seed規則を使用。既存 `benchmark-v1` の条件C 15/20/25爆弾を再計算し、採用率とattempt数が保存結果と完全一致した。
- 初手: center / near-center / edge / corner / random の5種類。
- 同じ候補Seedを3色・4色で評価し、専用No-Guess / 共通A / 共通Cを直接比較した。
- 3～40爆弾は全数調査。最終採用サンプルは計26,250候補。3～10=各500、11～23=各250、24～29=各500、30～34=各2,000、35～40=各1,000。
- 専用quality filterは6～30爆弾を各250候補で追加評価（計6,250候補）。
- 実生成時間は最大2,000 attempt。共通Cは8～28で計480生成、専用qualityは主要爆弾数で3色/4色合計300生成。
- 実行環境: Node v22.16.0。絶対時間は端末依存のため、iPhone/ブラウザ実測は製品実装前に再確認が必要。

## 初手開封

専用No-Guessだけで採用した場合の平均初手開封率は、3爆弾約96%、5爆弾約86%、8爆弾約66%、10爆弾約56%、11爆弾約50%、12爆弾約44%。3爆弾では約12%が初手だけでクリアした。

条件Cではcolor-essentialにより初手だけでクリアする盤面は今回の採用品では0%だったが、8爆弾のcenterでは平均約70%開く一方、cornerでは約16%で、**初手位置が難易度に大きく影響**した。高密度側ではcornerの採用率も悪化しやすい。

したがってランキング対象Endlessでは、初手を自由選択にせず、Stage Seedで決めた中央寄りセルを表示/自動開封する方式を推奨する。これにより公平性だけでなく次Stageの事前生成も可能になる。

## 爆弾数と難易度

- 爆弾数と難易度は**大局的には上昇傾向だが単調ではない**。専用No-Guess採用品のreasoning roundは8爆弾付近の約2.2から20爆弾付近の約7へ増えるが、22～29は採用品自体が希少になり平均値が揺れる。
- reasoning round、safe/mine deduction数、subset-difference使用回数は、爆弾数よりプレイヤー負荷を直接表す補助指標として有用。
- 初手開封率も重要。低爆弾数では爆弾数だけで難易度を決めると、盤面の大半が自動開封される。

## 共通盤面か色数別生成か

**Endlessは色数別生成を推奨する。** 3色/4色のランキングを分けるなら、同じ爆弾配置を共有させる必要はない。条件Cの「4色round ≤ 3色round」は3色と4色を直接比較するための条件であり、別部門Endlessでは生成コストに対する利点が小さい。

共通盤面を維持すべきなのは、3色と4色を同一ランキングで比較する場合、Daily Challengeのように同一盤面比較を売りにする場合などに限定する。

## 推奨Endless仕様

1. 9×9固定。3色/4色は選択後、その色専用の盤面を生成。
2. Stage 1は11爆弾。Stageごとに1個増やし、Stage 16で26爆弾。
3. Stage 17以降は26爆弾固定。面数は無制限に増える。初版では27以上へ増やさない。
4. 採用filterは上記quality filterを初期案とする。reasoning round / subset使用回数 / deduction数 / 初手開封率はログに残す。
5. 初手位置はプレイヤー自由選択にせず、Stage Seedで中央寄りに固定。全参加者で同じStage Seed列を使う。
6. ランキングは3色/4色別。主順位=クリアStage数、同Stageならアクティブプレイ時間をタイブレーク候補。生成待ち・広告時間は除外。
7. generator version / filter version / Stage→爆弾数 / Seed導出 / 初手位置 / maxAttempts / fallbackをランキング期間中に固定。途中変更時はランキング世代を分ける。
8. 広告はStage CLEAR後～次Stage開始前だけに置く。例: 5面ごと。広告中はタイマー停止。固定初手なら広告表示中に次盤面を事前生成できる。

## 上限到達・生成失敗時

- 26爆弾到達後は爆弾を増やさない。難易度を無理に上げるため条件を厳格化すると生成率が再び悪化するため、初版は「高難度を何面継続できるか」を競う。
- maxAttempts到達をゲームオーバー扱いにしてはいけない。ランキング公平性を壊すため、同じStageの次の決定論的Seed slotへフォールバックする仕様を固定する。
- 将来27以上を使う場合は、iPhone実機・ブラウザで専用quality生成を再ベンチし、p95と失敗率の基準を決めてから解禁する。

## 残る不確実性

- Node時間は製品端末の絶対時間ではない。特にiPhoneのWorker実測が必要。
- reasoning round等はSolver難易度であり、人間の体感難易度と完全一致しない。Labプレイテストで補正が必要。
- 30～34の成功例は極少数で統計誤差が大きい。35～40の0/1,000も不可能性の証明ではない。
- quality filterの50%/3round閾値は今回のデータからの初期案。製品実装前に10～14爆弾の体感確認で微調整可能。
