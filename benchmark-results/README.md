# 20爆弾ベンチマーク

固定条件: 9×9、20爆弾、各フィルタ×各初手シナリオ20回、最大2,000試行、
suite Seed `benchmark-v1`。全100生成/フィルタが上限内で成功した。

## Node v24.19.0

| 条件 | 採用率 | 平均試行 | p50 | p95 | worst | round 3色 / 4色 | subset 3色 / 4色 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A | 18.35% | 5.45 | 29 ms | 125 ms | 237 ms | 7.02 / 6.92 | 19.42 / 20.17 |
| B | 14.99% | 6.67 | 41 ms | 225 ms | 361 ms | 7.37 / 6.99 | 21.44 / 20.58 |
| C | 12.85% | 7.78 | 38 ms | 136 ms | 274 ms | 7.36 / 6.87 | 20.09 / 19.72 |
| D | 3.69% | 27.12 | 135 ms | 660 ms | 1,483 ms | 8.50 / 6.85 | 22.23 / 20.76 |

詳細値とシナリオ別内訳は [`node-20.json`](./node-20.json) に保存している。

主な読み取り:

- A〜Cはp95で約0.14〜0.23秒。初手後の同期生成でも検討可能な範囲だが、端末差を考えWorkerを標準とする。
- Dは採用率が約3.7%まで落ち、p95約0.66秒、worst約1.48秒。必須条件にすると待ち時間の裾が長い。
- 4色はB〜Dで3色より平均round数が少ない。Dはその差を強制する代わりに生成コストが大きい。
- 角初手はAで採用率13.2%、Dで2.3%と厳しく、中央付近より多くの試行を要する。

ランダム初手のworstが約928msあり、製品で採用する場合もWorker分離は維持する。

## 条件C・15/20/25爆弾比較

固定条件: 9×9、条件C、各爆弾数×各初手シナリオ20回、最大2,000試行、
suite Seed `benchmark-v1`。全100生成/爆弾数が上限内で成功した。

### Node v24.19.0

| 爆弾数 | 採用率 | 平均試行 | p50 | p95 | worst | round 3色 / 4色 | subset 3色 / 4色 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 15 | 21.60% | 4.63 | 26 ms | 168 ms | 278 ms | 5.62 / 5.26 | 17.98 / 17.35 |
| 20 | 12.85% | 7.78 | 30 ms | 102 ms | 279 ms | 7.36 / 6.87 | 20.09 / 19.72 |
| 25 | 1.10% | 90.67 | 126 ms | 455 ms | 878 ms | 8.28 / 7.63 | 20.68 / 20.46 |

詳細値とシナリオ別内訳は
[`node-difficulties-c.json`](./node-difficulties-c.json) に保存している。

主な読み取り:

- 15爆弾は20爆弾より採用率が高く、生成時間も同等以下で、そのまま難易度候補にできる。
- 25爆弾は採用率が約1.1%まで下がり、平均約91試行を要する。
- 25爆弾は角初手が最も重く、平均179.65試行を要する。
- 3条件すべてで、条件Cの定義どおり4色の平均reasoning round数は3色以下になった。
- 3色Solverが不合格の候補では4色Solverを省略する短絡を入れ、採用Seedを変えずに
  25爆弾のp95を約1.08秒から約0.46秒へ短縮した。
- 25爆弾も全件生成には成功したが、製品ではWorker分離と短い生成中表示を維持する。

角初手p95約0.93秒、worst約1.50秒のため、製品では100〜150msを超えた場合に
短い生成中表示を出す。タイマーは生成完了後に開始する。
